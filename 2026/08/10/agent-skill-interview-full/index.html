面试回答准备：什么是 Skill？如何创建 Skill（完整版）

本文用于技术面试回答准备，适合在面试官要求深入说明 Skill 的概念、组成、创建流程和安全边界时使用。

如果面试时间有限，可阅读：《面试回答准备：什么是 Skill？如何创建 Skill（精简版）》。

一、什么是 Skill？

Skill 是面向 AI Agent 的一种可复用能力包，用于封装某一类任务所需的专业知识、触发条件、执行流程、安全边界和完成标准。

它不只是一段更长的提示词，而是一套可被 Agent 发现、加载和执行的能力模块。典型结构如下：

各部分职责分别是：

  • SKILL.md：定义触发条件、核心流程、安全边界和完成标准；
  • scripts/：存放可重复执行的确定性脚本；
  • references/：存放 API 文档、技术规范和故障排查资料；
  • assets/：存放模板、配置样例和静态资源。

Cursor 通常先根据 SKILL.md 中的 name 和 description 判断当前任务是否需要该 Skill；任务匹配后，再读取完整流程，并按需加载脚本、参考资料和模板。

因此，一个设计良好的 Skill 需要解决三个核心问题：

  1. 什么时候使用：触发条件必须准确，避免该触发时不触发，或者无关任务频繁误触发；
  2. 如何稳定完成任务：需要有明确流程、校验步骤和完成标准；
  3. 权限边界在哪里：部署、发布、删除、发消息等高风险操作，必须在用户明确授权后执行。

从 Java 工程化角度理解，Skill 可以类比为一个面向 Agent 的能力模块：

  • description 类似能力发现和任务路由条件；
  • SKILL.md 类似流程编排与接口契约；
  • scripts/ 类似稳定、可测试的基础设施实现；
  • references/ 类似开发规范和 API 文档；
  • 安全规则类似权限控制与事务边界。

不过，这只是帮助理解的类比。Skill 的本质仍是 Agent 的能力封装机制，而不是 Java 类库或传统插件。

二、什么场景适合创建 Skill？

适合创建 Skill 的任务通常具有以下特点：

  • 会重复发生；
  • 有相对稳定的处理流程；
  • 需要专业知识或固定规范；
  • 仅靠临时提示词容易遗漏步骤；
  • 可能需要配套脚本、模板或参考资料。

例如：

  • 按团队规范审查 Java 代码；
  • 将 Word、PDF 或课件整理成技术博客；
  • 发布 Hexo 文章；
  • 生成服务容量评估报告；
  • 将文章安全推送到公众号草稿箱。

以下场景通常不必创建 Skill：

  • 只执行一次的临时任务；
  • 一两句话就能说清楚的个人偏好；
  • 必须始终生效的简单项目约束；
  • 单纯的定时任务；
  • 只有外部服务连接，没有稳定业务流程的能力。

例如，统一缩进更适合项目规则，定时检查更适合自动化任务，连接外部数据库则通常需要 MCP 或专用工具。

三、如何创建 Skill？

1. 明确能力范围和任务终点

首先需要回答：

  • 这个 Skill 解决什么问题？
  • 哪些请求应该触发它？
  • 哪些请求不属于它？
  • 执行到什么状态才算完成？

例如，“发布一篇文章”可能仅表示生成 Markdown，也可能包括本地构建、推送远程仓库以及验证线上页面。不同终点对应不同权限和风险，因此必须提前定义。

4. 使用渐进式加载拆分内容

不要把全部知识、示例和脚本都塞进 SKILL.md。更合理的方式是：

  • 核心流程放入 SKILL.md；
  • 确定性操作放入 scripts/；
  • 长篇规范放入 references/；
  • 模板和静态资源放入 assets/。

Agent 启动时主要使用名称和描述发现 Skill，匹配任务后读取完整 SKILL.md，真正需要时再读取其他资源。这种渐进式加载方式可以降低上下文成本。

主 SKILL.md 应保持精炼。开放 Agent Skills 规范建议将其控制在 500 行以内，详细资料按需拆分。

5. 将确定性操作脚本化

Skill 适合负责判断、规划和流程编排；脚本更适合完成稳定、可重复的操作，例如：

  • 校验标题长度；
  • 检查参数格式和取值范围；
  • 转换文件格式；
  • 检查图片尺寸；
  • 调用稳定 API；
  • 验证配置文件；
  • 执行构建和测试。

脚本至少应该具备：

  • 参数类型、格式和范围校验；
  • 正确处理包含空格的文件路径；
  • 执行失败时返回非零退出码；
  • 提供可以指导排查的错误信息；
  • 不在日志中泄露令牌、密码等敏感信息。

6. 设置安全边界

以下操作通常需要用户明确确认：

  • 部署生产环境；
  • 推送远程仓库；
  • 发布或群发内容；
  • 删除数据；
  • 修改权限；
  • 发送外部消息；
  • 执行可能产生费用的操作。

同时还应避免：

  • 将密钥写入 SKILL.md 或代码仓库；
  • 关闭 TLS 证书校验；
  • 将未经校验的用户输入直接拼接成系统命令；
  • 默认执行不可逆操作；
  • 把“生成内容”错误理解成“授权发布”。

7. 测试与验收

创建完成后，至少测试以下场景：

  1. 应该触发时是否能够触发；
  2. 不应该触发时是否保持静默；
  3. 输入缺失时是否会提出必要问题；
  4. 脚本失败时是否会停止后续流程；
  5. 高风险操作前是否会请求确认；
  6. 执行结果是否满足预先定义的完成标准。

四、面试总结

Skill 的核心不是把提示词写得更长，而是将可复用任务沉淀为一个触发准确、执行稳定、边界清晰的 Agent 能力模块。

创建 Skill 时，应先明确适用场景和任务终点，再设计 name、description 与执行流程；复杂内容通过 scripts/、references/ 和 assets/ 拆分；最后补充安全控制和测试验收。
