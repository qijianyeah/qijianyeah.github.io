大模型破冰之旅

从人工智能、机器学习、深度学习，一路走到大语言模型：先把概念地图立住，再谈选型、微调和落地。

1. 学习路线

大模型学习没有唯一正确顺序，但有一条不容易走弯路的主线：先会用，再理解，最后才定制。

阶段 目标 建议投入 产出
概念破冰 搞清 AI / ML / DL / LLM 的包含关系 1～2 天 能用自己的话讲清「大模型是什么」
上手调用 用 API 或本地 Ollama 跑通一轮对话 2～3 天 一个能聊天的 Demo
提示词与应用 Prompt、RAG、工作流、Agent 1～2 周 知识问答 / 客服 / 办公助手
私有化部署 Ollama、vLLM、量化、显存估算 3～5 天 本机或内网可调用的模型服务
模型定制 数据清洗、LoRA / PEFT、评测 按项目 领域更准、幻觉更少的专用模型
工程落地 鉴权、成本、监控、安全、评测集 持续 可上线的业务系统

入门阶段优先走「调用现成模型」：先把 DeepSeek、通义千问、ChatGPT 这类接口跑通，再考虑本地部署。微调是后半程的事——没有高质量数据和评测，微调往往不如 RAG。

一条可执行的最小路径：

  1. 读完本文的概念部分，画出「AI ⊃ 机器学习 ⊃ 深度学习 ⊃ 大模型」这张图。
  2. 用 Python 调一次兼容 OpenAI 协议的 API，完成一轮问答。
  3. 用 Ollama 在本机拉起一个 7B 量化模型，对比云端 API 的效果与延迟。
  4. 做一个最小 RAG：本地文档 → 切片 → 向量检索 → 拼进 Prompt。
  5. 有真实业务数据后，再评估要不要微调。

2. 学习方法

基础不同，切入点不同。同一套资料，零基础硬啃微调和有工程经验的人直接上 RAG，效率差一个数量级。

背景 先学什么 刻意避开什么 检验标准
零基础 Python 基础、命令行、Git；再用网页版大模型建立体感 一上来推公式、从零实现 Transformer 能独立安装环境，并能讲清「输入 → 模型 → 输出」
有编程基础 API 调用、Prompt、RAG、LangChain / Dify 过早陷入论文细节 一周内做出一个带检索的问答 Demo
有工作经验 选型、成本、私有化、安全合规、评测与监控 只玩 Demo、不谈上线约束 能给出「开源 / 闭源、云端 / 本地」的决策表

三条通用方法：

  • 用任务驱动：不要「先学完再做」。目标写成「本周做一个合同摘要助手」，缺什么补什么。
  • 先黑盒后白盒：先当用户把模型用熟，再回头看 Tokenizer、注意力、KV Cache。
  • 建立自己的评测集：准备 20～50 条真实业务题，每次换模型、换 Prompt、换 RAG 都用同一套题对比，避免凭感觉选模型。

3. 硬件准备

入门门槛比想象中低：内存 ≥ 16GB 就可以开始。没有独立显卡也能学完整条应用开发链路。

场景 最低配置 更舒服的配置 说明
只调云端 API 8GB 内存笔记本即可 任意现代电脑 算力在服务商侧，本机几乎无压力
本机跑 7B～8B 量化模型 16GB 内存 32GB 内存 + 苹果芯片 / 8GB 显存 Ollama + Q4 量化是常见组合
本机跑 14B 及以上 32GB 内存 24GB 以上显存 速度和并发都会明显下降
微调 7B LoRA 至少 16GB 显存 24GB / A10 / 4090 显存不够就租云 GPU，不必先买卡

没有显卡时的策略：

  • 日常对话、Prompt、RAG、Agent、Dify 全部走 API。
  • 真正要微调时，按小时租一张 4090 / A10 / A100，训完即释放。
  • Mac（Apple Silicon）对 Ollama 比较友好，适合本地体验，不适合当作大规模训练机。

先把「能跑起来」放在「能训起来」前面。硬件是瓶颈时，优先减小模型或改用 API，而不是停在环境上。

4. 语言准备

大模型这条线上，Python 是默认工作语言，但不要求把主语言换成 Python。

语言 角色 典型用途
Python 必学 调 API、数据处理、LangChain、微调脚本、评测
Java / Go / C++ 等 可继续作为主语言 业务系统、网关、高并发服务里调用模型 HTTP 接口
JavaScript / TypeScript 加分 前端对话界面、Node 服务、部分 Agent 工具链
SQL 经常用到 日志分析、评测结果统计、业务数据抽样

Java 工程师常见路径：业务服务仍用 Spring，模型调用走 HTTP / SDK；数据处理和微调脚本用 Python。两套语言并存是常态，不是缺陷。

5. AI 必备概念

5.1 从人工智能到大模型

大模型不是突然出现的新学科，而是套在已有技术栈里的一层。包含关系从外到内是：

人工智能 ⊃ 机器学习 ⊃ 深度学习 ⊃ 大模型

时间线上可以记住四个锚点：

年代 阶段 典型特征
1950 年代起 人工智能 符号推理、专家系统、让机器「像人一样解决问题」
1980 年代起 机器学习 从数据里学规律，不再把全部规则手写死
2010 年代起 深度学习 多层神经网络自动提取特征，ImageNet 之后全面爆发
2020 年代起 大模型 Transformer + 海量数据 + 大规模算力，泛化能力显著跃升

后一层是前一层的实现路径，不是替代关系。今天做大模型应用，仍然在用机器学习的训练/评测思路，仍然在用深度学习的网络结构。

5.2 机器学习

机器学习是实现人工智能的一条主路径：从数据中找出规律，再用这条规律对未知样本做预测、分类或决策。样本越多、特征越有效、算法越匹配任务，结果通常越准。

以「自动识别汽车」为例，传统机器学习大致四步：

  1. 准备样本：收集大量汽车 / 非汽车图片或结构化记录。
  2. 提取特征：高度、颜色、车轮、车身轮廓等。这一步过去高度依赖人工经验。
  3. 选择并训练算法：把特征喂给模型（一套可学习的数学公式），让它在标注数据上调整参数。
  4. 推理：把未知样本的特征送进训练好的模型，得到「是不是汽车」的结论。

抽象成一条流水线：

  • 输入：数据集，也就是准备好的样本。
  • 算法 / 模型 / 数学公式：对数据做训练的那套可学习结构。业务方通常不从零发明算法，而是选用已有结构（逻辑回归、树模型、CNN 等），再在自己的数据上训练。
  • 输出：类别、分数、决策结果。

这里有三个容易混的动作，必须分开：

动作 谁来做 含义
创建算法 研究者 / 算法工程师 发明 CNN、Transformer 这类结构
使用算法 你 在 PyTorch / TensorFlow 里调用现成结构
训练模型 你 用自己的数据更新参数，得到专用权重

继续用汽车识别拆开：

  1. 用算法：不必从零推导 CNN。打开工具包，调用 torchvision.models.resnet50()，这一刻是在使用现成结构。
  2. 训练模型：准备例如 10 万张标注图片，喂给 ResNet50。数百万内部参数会按数据自动调整；学习率、训练轮数等超参数由你控制。训完后，通用的 ResNet50 变成「专门认车」的模型，保存为 my_car_detector.pth。
  3. 上线推理：加载这份权重，对新图片输出「这是汽车，置信度 97%」。

一句话：用的是别人的结构，训出的是自己的参数。

5.3 深度学习

深度学习是机器学习的一个子集，核心差异在特征还要不要人来设计。

对比项 传统机器学习 深度学习
特征 人工设计，依赖领域经验 多层网络从原始数据里自动学习
数据量 中小规模也能工作 通常更吃数据
可解释性 相对更好讲清 内部表示更黑盒
典型任务 表格预测、经典分类 图像、语音、自然语言

深度学习把更简单的变换一层层叠起来：数据从输入层进入，经过多个隐藏层，到达输出层。每一层都在组合上一层的表示，从而形成更复杂的概念——边缘、零件、物体，或词、句、语义。

常见应用：

方向 例子
图像 物体识别、场景识别、车型识别、人脸检测与认证
自然语言 机器翻译、文本分类、对话生成
语音 语音识别、语音合成

大语言模型走的就是深度学习这条路，只是网络更深、数据更广、参数更大，任务从「分类 / 识别」扩到了「生成」。

5.4 神经网络

神经网络（Artificial Neural Network，ANN）是深度学习的代表算法之一，广泛用于图像分类与检测、文本分类与对话等任务。它是一种模仿生物神经系统结构与功能的计算模型。

人脑由大量神经元连接而成：

单个生物神经元的结构可以记四个部件：

生物结构 作用 人工神经元里的对应物
树突 接收其他神经元传来的信号 输入 x_i 与权重 w_i
细胞核 / 胞体 汇总并处理信号 加权求和 + 激活函数
轴突 把处理结果传出去 输出 y
轴突末梢 / 突触 接到下一颗神经元的树突 层与层之间的连接

人工神经网络把大量这样的计算单元按层排列：

  • 输入层：接收原始数据（像素、词向量、表格字段等）。
  • 隐藏层：一层或多层都可以；层数和每层神经元个数是结构超参数。
  • 输出层：给出分类分数、生成下一个 token 的概率等。

层与层之间的连线就是可学习的权重。训练的本质，是根据预测误差反复调整这些权重。

想直观感受「加一层、改几个神经元、决策边界如何变」，可以用 TensorFlow Playground：https://playground.tensorflow.org/

在这个页面里可以看到：

  • 左侧选择输入特征（如 X1、X2）。
  • 中间隐藏层的每个神经元学到一块局部判别图案。
  • 右侧输出层画出分类边界，并显示训练损失 / 测试损失。
  • 连线粗细表示权重大小，颜色表示正负。

它解决的是二维点分类，和 GPT 不是同一个模型，但「输入 → 隐藏层变换 → 输出」这条骨架是一样的。大模型只是把层数、宽度、数据模态和训练规模全部放大，并把核心结构换成了 Transformer。

5.5 大语言模型

大语言模型（Large Language Model，LLM）是面向自然语言处理设计的深度神经网络。它仍然是「输入 → 深层网络 → 输出」，只是输入输出都是 token（子词），训练目标通常是根据上文预测下一个 token。

大模型的「大」，至少有四层含义：

维度 含义
训练数据大 网页、书籍、代码、对话等海量文本，部分语料规模达到 TB / PB 量级
参数规模大 从数十亿到数千亿参数，决定模型能记住和组合多少模式
算力大 依赖 GPU / TPU 集群和分布式训练框架
泛化能力强 预训练后，只需少量提示或少量样本，就能覆盖问答、翻译、摘要、代码等多种任务

为什么近几年才爆发

技术储备早就有了，真正把规模推上去的是四件事同时成熟：

  • 硬件：GPU、TPU 让千亿参数训练从「理论上可行」变成「工程上可做」。
  • 算法：Transformer（2017）用自注意力处理长距离依赖，比 RNN 更适合并行训练。
  • 数据：互联网文本、代码、多模态数据爆炸，预训练有了燃料。
  • 工程：PyTorch、Megatron、DeepSpeed 等分布式框架让万卡训练可落地。

ChatGPT 让「对话式通用接口」被大众看见，但底座是上面这条链路，不是某一个产品名。

6. 常见大模型介绍

选型时先分清三件事：谁训练的、开不开源、擅长什么。同一家公司往往同时提供对话产品和可部署的基座模型，不要把「网页 Chat」和「可微调的权重」当成同一个东西。

模型 发布方 开源情况 主要特点
DeepSeek 深度求索 权重开源 推理与 Agent 能力突出，性价比高
通义千问 阿里巴巴 开源 编程与中文能力强，上下文长，部署生态完整
文心 4.5 系列 百度 开源 多模态 MoE，覆盖理解与生成
豆包大模型 字节跳动 部分开源 偏商业落地，强调速度与性价比
腾讯混元 腾讯 部分开源 多模态与 3D 生成有特色
Kimi / K2 月之暗面 部分开源 长上下文、复杂任务与浏览式研究
GPT 系列 OpenAI 主力闭源，另有开源线 综合能力标杆，工具调用与智能体成熟
Claude 系列 Anthropic 闭源 安全对齐、长上下文、代码与文档能力强
Llama 系列 Meta 开源（有许可约束） 全球最主流的开源基座之一
Gemini 系列 Google 主力闭源 原生多模态，和搜索 / 工具生态结合紧

开源不等于「训练数据与完整流程全部公开」，多数情况下公开的是模型权重与推理代码。闭源也不等于不能用，只是你只能走 API，改不了结构和参数。

7. 大模型选型

先决定「开源还是闭源」，再决定「哪一家、哪一档尺寸」。

维度 开源大模型 闭源大模型
可审查性 权重可下载、行为可复现、便于安全审计 黑盒，内部数据与对齐过程不可见
定制能力 可微调、可改解码、可做领域适配 通常只能调 Prompt / 工具，改不了底层参数
成本结构 前期硬件和工程投入高，后期边际成本低 按 Token 计费，流量一大账单上升很快
效果上限 中小规模场景已很好；头部闭源在综合能力上仍常领先 综合推理、多模态、工具生态往往更完整
运维 自己负责部署、升级、扩容、安全补丁 供应商运维，业务侧接入快
数据主权 可完全本地化，适合强合规 数据要出域，需评估脱敏和合同条款

经验上的默认策略：

  • 要快上线、要最强推理、数据可以出域：闭源 API。
  • 要私有化、要可控成本、要领域微调：开源权重 + 本地 / 专有云部署。
  • 多数企业会两头都用：办公助手走 API，核心业务走私有化。

即使选定同一系列，型号不同，能力也完全不同。以通义千问为例，控制台里同时存在视觉理解、语音识别、语音合成等不同产品：

选型时不要只写「用千问 / 用 GPT」，要写到具体型号，并确认：

  1. 模态：纯文本，还是视觉、语音、视频。
  2. 上下文长度：长文档、多轮工具调用能不能塞进去。
  3. 延迟与价格：Flash / Mini 类适合高并发；Max / 思考模型适合难题。
  4. 部署形态：公有云 API、专有云，还是开源权重本地推理。
  5. 许可：开源权重是否允许商用、是否限制用户规模。

8. 通用基础大模型 vs 行业垂直大模型

通用基础大模型在海量通用语料上预训练，目标是「什么都能聊一点」。ChatGPT、DeepSeek、Kimi、豆包、通义千问都属于这一层的代表产品：

行业垂直大模型则是在通用能力之上，用专业数据继续训练或对齐，让模型在医疗、金融、法律、工业等场景里更懂术语、更守规范、更少胡编。

从行业落地路径看，相当比例的企业并不是直接把通用 Chat 塞进生产，而是走垂类模型或「通用模型 + 领域数据」的组合。下图中，垂类路径约占六成：

类型 优势 代价 更适合
通用基础模型 能力面宽，生态新、迭代快 领域术语弱，容易幻觉 办公、编程、通用问答、原型
行业垂直模型 术语、流程、合规更贴业务 数据建设成本高，要持续更新 医疗、金融、法律、政务、工业质检

垂类不等于必须从零预训练。更常见的三层做法是：

  1. Prompt + 规范：把行业话术、禁止事项写进系统提示。
  2. RAG：把制度、病历规范、产品手册检索进上下文。
  3. 微调：在前两步仍不够稳时，再用领域数据改模型行为。

多数业务在 1 和 2 就能上线，3 是增强项。

9. 大模型微调

通用模型在专业领域会表现出「看起来很懂、细节经常错」——也就是幻觉。把高质量的领域数据交给模型做继续训练，就是微调。目标不是让模型变得更大，而是让它在你的任务分布上变得更准。

一个常用工具链是 LLaMA-Factory，把数据格式、LoRA、训练脚本和导出流程收在一起。完整过程可以记成四步：

步骤 关键点
选基座 中文任务优先选中文表现好的开源模型；尺寸按显存来，7B / 14B 最常见
准备数据 指令格式（instruction / input / output），宁缺毋滥，先保证正确再追求量
选择算法 入门用 LoRA / QLoRA，少改原权重、显存占用低
训练 盯 loss、学坏了的样本、过拟合；保存多个 checkpoint
评测 用训练时没见过的真实题目，对比「原模型 vs 微调模型 vs RAG」
发布 合并 LoRA 或保持适配器分发；用 vLLM / Ollama 对外提供服务

微调解决的是「风格、格式、领域口径」，RAG 解决的是「事实和最新知识」。制度每月都变，优先 RAG；希望模型稳定按某种 JSON 或公文格式说话，优先微调。两者经常一起用。

10. 行业应用、趋势与挑战

10.1 已经铺开的行业与场景

金融、医疗、工业、教育、科研、媒体、通信、政务、营销、交通、文娱、城市治理、法律、汽车、运维等行业都已经有可落地的切口。相对成熟的场景包括：

类别 场景
对话与办公 智能客服、智能问答、公文写作、会议纪要、智慧办公
检索与决策 智能搜索、知识库问答、舆情监控、智能风控
研发与运维 代码助手、日志分析、故障辅助定位
业务办理 政务咨询、业务预审、合同校对
行业知识 诊疗知识库、投研助手、法规检索
交互形态 虚拟数字人、多模态质检、语音坐席

判断一个场景值不值得做，看三件事：有没有稳定的知识来源、容不容错、能不能评测。客服和知识问答容易起步；直接让模型做不可逆的金融或医疗决策，必须加人工审核。

10.2 趋势

技术侧：

  • 模型继续变强，但也会更强调效率：同样效果，更小的模型和更快的推理更受欢迎。
  • 多模态成为默认能力：文本、图像、语音、视频不再分家。
  • 可解释性与可控性会被产品化：引用出处、拒绝回答、权限隔离不再是论文话题。

应用侧：

  • 垂直化：行业模型和领域 Agent 会比「全能聊天」增长更快。
  • 端侧部署：手机、PC、工控机上的小模型会分担一部分云端调用。
  • UGC + AIGC：用户内容与模型生成内容会混在同一条生产链路里，版权和审核会同步变严。

10.3 挑战

类别 具体问题 工程上的应对
安全与伦理 偏见、越狱、有害内容、深度伪造 系统提示、安全护栏、输出过滤、人工复核
数据与模型治理 训练数据版权、日志留存、模型版本混乱 数据分级、提示词与权重的版本管理
人机协作 全自动不可靠，全人工又浪费 人机回路：模型起草，人确认关键步骤
幻觉 编造法规条文、伪造引用 RAG 强制引用、拒绝无依据回答、评测集回归
资源与环境 训练和推理耗电、显卡昂贵 量化、缓存、小模型路由、按需扩容
普及不均衡 中小团队缺算力、缺数据、缺评测 先 API 后私有化，先 RAG 后微调

破冰阶段最有用的心态是：先做出一个可评测的小闭环，再决定要不要更大的模型、更多的卡、更重的微调。 概念地图清楚之后，其余都是工程问题。
