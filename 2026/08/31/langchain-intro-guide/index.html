LangChain 介绍完全指南：从框架由来到 Agent 快速上手

发表于2026-08-31|更新于2026-08-31|AI 工程实践
|浏览量:

LangChain 是用于开发由大语言模型（LLM）驱动的应用程序的开源框架。它不只是对模型 API 的简单封装，还提供预构建的 Agent 架构和丰富的工具集成，让你不必从零搭建复杂链路，就能快速构建 RAG、对话机器人、数据问答等应用。

1. LangChain 的由来

LangChain 诞生于 2022 年 10 月，由 Harrison Chase 创建。名称来自 Language（语言模型）+ Chain（链式连接），核心思路是：把大模型与外部工具、数据源、记忆机制链式组合，构建更强的 AI 应用。

1.1 为什么需要 LangChain

单一 LLM 能力虽强，但在真实业务里常遇到三类局限：

局限 说明
知识时效 训练数据有截止时间，难以覆盖最新信息
无法直连外部系统 不能直接查数据库、调 API、读企业文档
无状态 难以在多轮对话中保持连贯上下文

LangChain 的设计目标，就是把 LLM 与工具、数据源、记忆有机结合，补齐上述短板。

1.2 架构演进（LangGraph 与 v1.0）

  • 2024 年：随着应用从原型走向生产，开发者需要更精细的工作流控制。LangChain 团队推出 LangGraph 作为底层 Agent 编排框架；原有 Chain / Agent 部分能力逐步迁移到基于 LangGraph 的统一抽象。
  • 2025 年 10 月：发布 LangChain v1.0.0 与 LangGraph v1.0.0，框架进入更成熟、标准化的阶段。

官方文档：

  • 英文：https://docs.langchain.com/oss/python/langchain/overview
  • 中文：https://docs.langchain.org.cn/oss/python/langchain/overview

2. 核心特点

2.1 统一的模型接口

OpenAI、Anthropic、DeepSeek 等厂商 API 各不相同。LangChain 通过统一抽象层标准化模型交互，便于切换模型而无需大面积改代码，降低厂商锁定，方便试验新模型。

2.2 模块化架构

LangChain 将应用拆成可复用组件，常见包括：

组件 作用
Models 对接各类 LLM / Chat 模型
Prompts 提示词模板
Memory 对话记忆
Chains 组件串联（v1 后部分场景由 LangGraph 承接）
Agents 能选工具、做决策的智能体
Tools 可被 Agent 调用的外部能力

LCEL（LangChain Expression Language） 支持用管道符 | 把多个组件串成工作流，例如「检索 → 拼 Prompt → 调 LLM」的 RAG 链路，并天然支持流式、异步、并行等能力。

2.3 智能体与工具调用

Agent 把 LLM 从「被动生成文本」变成「观察 → 思考 → 行动」的循环：

  1. 分析用户问题
  2. 选择合适工具（搜索、数据库、API 等）
  3. 执行工具并根据结果决定下一步
  4. 直到任务完成

工具通常是带名称、描述、执行函数的标准接口，Agent 据此自动决定是否调用。

2.4 记忆管理

记忆系统解决 LLM 应用「无状态」问题，支持短期 / 长期记忆及多种存储后端（内存、文件、数据库）。例如客服需要长期记住用户偏好，而一次性查询可能只需当前会话上下文。

3. 典型使用场景

3.1 检索增强生成（RAG）

将文档、知识库向量化，回答前先检索相关内容，再交给 LLM 生成答案。用于缓解知识滞后和幻觉问题。

3.2 Agent 智能体

以 LLM 为推理引擎，自主规划并执行多步任务。例如：

  • 旅行规划：依次查航班、订酒店、推荐景点
  • 市场调研：检索报告、汇总分析
  • 数据分析：自然语言转 SQL 并执行

3.3 对话系统与聊天机器人

结合 Memory 与外部工具，构建上下文感知的对话应用：电商客服查订单、教育助手结合教材答疑等。

3.4 数据连接与处理

  • 从 PDF / 合同提取关键字段
  • 自然语言查询数据库
  • 基于 Excel 生成分析报告

3.5 内容生成与自动化写作

通过 Prompt 模板与输出解析器，生成结构化文档：周报、邮件、法律文书等。

3.6 多模态应用

结合图像、语音等能力：上传图片生成描述再问答、语音转文本处理后再 TTS 输出等。

5. 小结

维度 要点
定位 LLM 应用开发框架，链式组合模型、工具、记忆
演进 LangGraph 负责编排；v1.0 后架构更统一
核心能力 统一模型接口、模块化、Agent、Memory
常见场景 RAG、Agent、对话、数据处理、内容生成、多模态
上手路径 Conda 环境 → 安装依赖 → .env + LLM → create_agent

下一步可继续学习：RAG 文档加载与向量库、更多 Tool 接入、LangGraph 工作流编排。
