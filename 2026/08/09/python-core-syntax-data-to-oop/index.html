2. 流程控制：条件、模式匹配与循环

Python 程序默认按照代码的书写顺序从上到下执行。流程控制语句可以改变这条执行路径：

  • 条件判断：根据条件选择要执行的分支。
  • 模式匹配：根据值或数据结构选择分支。
  • 循环：重复执行一段代码，直到遍历结束或终止条件成立。

5.2.5 通配符导入

  • 模块新增公开名称后，使用方可能在未修改代码的情况下发生冲突。
  • 静态检查、自动补全和重构工具更难准确分析代码。

交互式探索中偶尔会使用通配符导入；可维护的项目代码应显式导入模块或所需名称。

6.2 类与对象

6.2.1 类是模板，对象是实例

类（class）描述一组对象共同拥有的数据和行为，是创建对象的模板；对象（object）是根据类创建出的具体实例，也称实例对象。

例如，“学生”可以作为类；“学号为 1001、姓名为小林的学生”则是一个具体对象。同一个类能够创建多个相互独立的对象。

6.2.2 定义类与创建对象

Python 使用 class 关键字定义类。类名通常使用大驼峰命名法，例如 UserInfo、BankAccount。类体中可以定义属性和方法。

执行 BankAccount("小林", 100.0) 时，Python 先创建实例，再自动调用初始化方法 __init__。变量 account 保存对该实例的引用，之后可通过 account.deposit(...) 调用实例方法。

6.3 属性：对象保存的数据

6.3.1 实例属性

实例属性属于某个具体对象，通常在 __init__ 中通过 self.属性名 定义。每个对象都有自己的实例属性，修改一个对象不会影响其他对象。

虽然 Python 允许在对象创建后动态增加属性，例如 dog1.color = "白色"，但这会导致同一类的不同实例拥有不一致的结构。除非确有动态建模需求，通常应在 __init__ 中统一初始化实例属性。

6.3.2 类属性

类属性写在类体中、方法之外，属于类本身，并由所有实例共享。共享配置、计数器等数据适合使用类属性。

6.5 常用魔法方法

魔法方法也称特殊方法，名称通常以双下划线开头和结尾，例如 __init__、__str__。它们定义对象如何参与 Python 的内置操作。通常不直接写 obj.__str__()，而应使用会触发它的公开操作，例如 str(obj) 或 print(obj)。

6.9 异常基础

6.9.1 什么是异常

异常是程序运行期间出现的非正常事件。例如，变量不存在、类型不匹配、索引越界或输入格式错误都会触发异常。如果异常沿调用栈向上传递后仍未被处理，当前程序会终止并输出追踪信息。

异常不等同于所有 Bug。Bug 是程序缺陷的统称，既包括会触发异常的问题，也包括程序正常运行却得到错误结果的逻辑错误。异常则是 Python 提供的一套错误报告与控制机制。

KeyError 字典中不存在指定键

6.9.2 为什么要处理异常

捕获异常的目的不是隐藏错误，而是对可以预期且可以处理的失败提供方案，例如：

  • 提示用户重新输入；
  • 文件不存在时使用默认配置；
  • 网络请求失败时执行有限次数重试；
  • 回滚已完成一部分的操作；
  • 记录上下文后让上层决定如何处理。

无法合理恢复的异常不应被静默吞掉，否则程序可能在错误状态下继续运行。

6.10 try、except、else 与 finally

6.10.1 完整执行流程

try 中放置可能引发异常的代码；except 只处理匹配的异常；else 在 try 没有发生异常时执行；finally 无论是否发生异常都会执行，适合完成必要的收尾工作。

执行规则如下：

  1. try 无异常：跳过所有 except，执行 else，最后执行 finally。
  2. try 出现匹配异常：从出错位置跳转到对应 except，不执行 else，最后执行 finally。
  3. try 出现未匹配异常：仍执行 finally，然后异常继续向上层传递。

try 应尽量只包含确实可能失败的语句，避免意外捕获同类型但来源不同的错误。不会抛出目标异常的后续逻辑可放进 else，使错误边界更清晰。

6.10.2 捕获具体异常

优先捕获具体异常，才能针对不同原因给出准确处理。多个异常处理方式相同时，可以写成异常元组。

不要使用空的 except:，因为它连 KeyboardInterrupt、SystemExit 等程序控制异常也会捕获。except Exception 虽然范围更合理，但仍不应作为默认选择；只有在应用边界需要统一记录、清理或转换错误时才考虑使用，并且通常要继续抛出异常。

6.10.3 获取异常信息与主动抛出

except ... as error 可以取得异常对象。使用 raise 可主动报告不合法状态；在 except 中单独写 raise，可以保留原追踪信息并继续向上抛出。

6.11 异常传递

异常传递是异常沿函数调用栈逐层向上报告的过程。某一层没有处理异常时，调用它的上一层便有机会处理；如果一直无人处理，解释器会输出 traceback 并终止当前程序。

异常应在“知道如何处理”的层级捕获。底层函数通常负责准确报告失败，上层业务逻辑根据场景决定重试、使用默认值、提示用户或终止操作。

6.12 面向对象与异常处理实践原则

  1. 类应表达清晰的业务概念，并承担单一、明确的职责。
  2. 在 __init__ 中建立完整、有效的初始状态，避免对象创建后长期处于“半初始化”状态。
  3. 实例独有的数据使用实例属性，共享配置或统计信息才使用类属性。
  4. 使用 self 访问当前对象的数据和行为，不依赖难以追踪的全局状态。
  5. 只实现业务真正需要的魔法方法，并遵循 Python 对这些方法的语义约定。
  6. 不依赖 __del__ 释放关键资源；使用 with、上下文管理器或显式的 close 方法。
  7. 在程序边界校验外部输入，在对象内部维护自身不变量。
  8. 捕获能够实际处理的具体异常，不用宽泛捕获来掩盖程序缺陷。
  9. 清理操作放在 finally 或上下文管理器中；正常路径逻辑可放在 else 中。
  10. 让异常传递到最了解业务恢复策略的层级，必要时使用异常转换保留清晰的错误语义。
