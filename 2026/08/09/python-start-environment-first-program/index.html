1. 认识 Python

1.1 编程语言是什么

自然语言帮助人与人交流，编程语言则是一套让人向计算机描述数据和操作的形式化规则。计算机底层只能直接处理二进制指令，人编写的 Python 源代码不能被 CPU 直接执行，需要由 Python 解释器读取并执行。

因此，学习 Python 不只是记忆语法，还要准备两个基本工具：

  • Python 解释器：负责执行 Python 代码，是运行程序的必要条件。
  • 代码编辑器或 IDE：负责高效编写和管理代码，例如 PyCharm、Visual Studio Code。

1.2 Python 的由来与特点

Python 由荷兰计算机科学家 Guido van Rossum（吉多·范罗苏姆）设计，首个公开版本发布于 1991 年。它是一门高级、通用、跨平台的编程语言，主要特点包括：

  • 语法简洁：代码可读性强，适合初学者快速入门。
  • 生态丰富：拥有大量成熟的第三方库和开发工具。
  • 应用广泛：可用于 Web 开发、数据分析、人工智能、自动化运维、测试、爬虫和桌面工具等领域。
  • 跨平台：同一份代码通常可以在 Windows、macOS 和 Linux 上运行。
  • 解释执行：通常由解释器在运行时执行代码，便于调试和快速迭代。

“解释型语言”是对典型使用方式的概括，并不表示 Python 完全不编译。以常用的 CPython 为例，源代码通常会先转换为字节码，再由 Python 虚拟机执行。

2.3 解释器与交互模式

Python 交互模式适合快速验证一两行代码：输入一条语句，解释器就执行一条语句。它的优点是反馈及时，但输入历史不适合作为正式项目保存。

需要反复运行或一次执行多行代码时，应把代码保存到扩展名为 .py 的文本文件中，再让解释器执行该文件。两种方式使用的是同一种 Python 语法，区别主要在于代码是否被持久保存。

4. 理解 PATH 环境变量

4.1 PATH 的作用

环境变量是操作系统为进程提供的一组配置值，例如临时目录、用户目录和可执行程序的搜索路径。PATH 是其中最常用的一项，它保存了一组目录。

在终端输入 python 时，操作系统大致按以下顺序处理：

  1. 判断它是否为终端自身支持的命令。
  2. 在当前规则允许的位置以及 PATH 列出的目录中查找对应的可执行文件。
  3. 找到后启动程序；找不到则报告命令不存在。

因此，配置 PATH 的目的不是“安装 Python”，而是让操作系统知道应该去哪里查找 Python 可执行文件。

Windows 中常见的 Python PATH 项包括 Python 安装目录和它的 Scripts 子目录，例如：

Python\ 目录使 python 命令可用，Scripts\ 目录则通常包含 pip 等命令。

4.2 Windows 手动配置 PATH

如果安装时没有勾选添加 PATH，可按以下步骤补充：

  1. 确认 Python 的实际安装目录，不要直接照抄示例路径。
  2. 打开“设置 → 系统 → 系统信息 → 高级系统设置”。
  3. 进入“环境变量”。
  4. 在当前用户的变量或系统变量中选择 Path，点击“编辑”。
  5. 分别新增 Python 安装目录和 Scripts 目录。
  6. 保存后关闭并重新打开命令提示符。
  7. 再次执行 python --version 验证。

“用户变量”只影响当前用户，通常权限要求更低；“系统变量”影响所有用户，修改时一般需要管理员权限。个人开发电脑优先配置用户级 Path 即可。

5. 使用 PyCharm 开发 Python

5.1 为什么使用 IDE

只用普通文本编辑器也能编写 Python，但随着代码增多，会缺少语法提示、错误检查、项目管理和调试支持。IDE（集成开发环境）把编辑器、解释器配置、运行器、调试器和版本控制等能力集成在一起，可以减少低级错误并提升开发效率。

常见 Python 开发工具包括 Visual Studio Code 和 PyCharm。PyCharm 是 JetBrains 推出的 Python IDE，对项目管理、代码补全、虚拟环境和调试提供了完整支持。

5.2 下载并安装 PyCharm

下载地址：https://www.jetbrains.com/pycharm/download/

安装完成后首次启动，PyCharm 会显示欢迎界面。不同版本的界面文字和布局可能略有差异，但核心操作一致。

5.3 创建项目并选择解释器

在欢迎界面选择“新建项目”，然后完成以下配置：

  1. 设置项目名称和存储位置，例如 D:\Python-Project\python_start。
  2. 选择解释器环境。初学阶段建议为每个项目创建独立的 .venv 虚拟环境。
  3. 选择虚拟环境所基于的 Python 3 解释器。
  4. 点击“创建”。

虚拟环境会为项目隔离第三方依赖，避免不同项目要求的包版本互相冲突。它不会复制一整套操作系统，只保存项目所需的 Python 环境和已安装软件包。

如果 PyCharm 提示“未配置 Python 解释器”，可打开设置，进入“Project → Python Interpreter”，选择已有解释器或创建新的虚拟环境。运行按钮不可用、导入包全部标红，也常与解释器未正确配置有关。

5.5 PyCharm 外观与字体配置

打开“Settings/Preferences”，可根据需要调整：

  • 主题颜色：进入“Appearance & Behavior → Appearance”选择亮色或深色主题。
  • 编辑器字体：进入“Editor → Font”调整字体、字号和行高。
  • 界面字体：在外观设置中调整菜单和工具窗口的字体。

配置应以清晰、易读为目标。字号过小容易疲劳，行高过窄会降低代码的可扫描性；初学时不必安装大量插件。

6. 认识 PyCharm 项目目录

一个刚创建的项目可能包含以下内容：

  • python_start/：项目根目录，集中保存本项目的代码和配置。
  • quick_start.py：开发者编写的 Python 源文件。
  • .idea/：PyCharm 生成的项目配置目录，保存解释器、运行配置和界面状态等信息。
  • .venv/：项目虚拟环境目录，包含隔离的解释器入口和第三方包。

PyCharm 项目窗口中还可能出现：

  • External Libraries：当前解释器可访问的标准库与第三方库视图，不是项目源码目录。
  • Scratches and Consoles：用于临时实验的草稿和控制台内容。

.idea 和 .venv 通常不应手动修改。项目使用 Git 时，.venv/ 一般不提交，因为它体积较大且可根据依赖清单重建；.idea/ 是否提交取决于团队约定。

7. Python 注释

7.1 注释的作用

注释是写给开发者阅读的说明，用于解释代码意图、关键约束或不容易理解的原因。执行程序时，普通注释不会作为语句运行。

好的注释应说明“为什么这样做”，而不是机械重复“代码做了什么”。变量和函数命名足够清楚时，不必为每一行都添加注释。

9. 入门常见问题速查

9.1 SyntaxError 语法错误

常见原因包括使用中文标点、引号没有成对、括号没有闭合或冒号缺失。根据错误信息中的文件名和行号定位代码，并重点检查报错位置及其上一行。

9.2 IndentationError 缩进错误

Python 使用缩进表示代码块。同一代码块的缩进必须一致，建议每一级使用 4 个空格，不要混用 Tab 和空格：

9.3 中文输出乱码

现代 Python 3 默认使用 Unicode，源文件建议保存为 UTF-8。若 Windows 旧版终端仍显示异常，可换用 Windows Terminal 或 PyCharm 终端，并确认编辑器文件编码和终端编码均为 UTF-8。不要为了绕过乱码而把中文改成拼音。

9.4 ModuleNotFoundError

这表示当前解释器环境中没有找到要导入的模块。初学阶段最常见的原因是 PyCharm 选择的解释器与安装依赖时使用的解释器不是同一个。应先确认解释器路径，再通过对应解释器安装依赖：

不要把示例中的“包名”原样执行，应替换为实际需要的包。

9.5 文件名导致导入冲突

不要把练习文件命名为 random.py、json.py、typing.py 等标准库模块名，也不要命名为 python.py。否则导入标准库时，解释器可能优先加载当前目录下的同名文件，造成难以理解的导入错误。
