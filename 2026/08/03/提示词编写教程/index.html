提示词编写教程

一、什么是提示词工程

提示词（Prompt）：发送给大模型的指令。

提示词工程（Prompt Engineering）：通过优化提示词，使大模型生成尽可能理想的内容。

常用做法包括：

  1. 清晰明确的指令
  2. 使用分隔符标记输入
  3. 按步骤拆解复杂任务
  4. 提供输入输出示例
  5. 明确要求输出格式
  6. 给模型设定一个角色

很多简单的 AI 应用，仅靠一段足够好的 System Prompt 就能跑起来（纯 Prompt 模式）。本文以「哄哄模拟器」提示词为例，说明如何系统化编写提示词。

二、提示词角色

与大模型对话时，消息通常包含三种角色：

角色 作用 示例
system 设定身份、规则、输出格式，优先级最高 你只能以女友身份回答……
user 用户本轮输入 在我心里你永远是最美的！
assistant 模型历史回复，用于会话记忆 (微笑)哼，我怎么知道……

业务规则应写在 System Prompt 中，不要依赖用户自觉遵守。

在 Spring AI 中，可在创建 ChatClient 时通过 .defaultSystem(...) 一次性设定。

六、编写与调优流程

  1. 先写最小可用版：角色 + 目标 + 输出格式
  2. 补规则：流程、分支、结束条件
  3. 加示例：至少一条成功、一条失败
  4. 加固边界：禁止串戏、禁止无关回答、防注入
  5. 实测调优：挂 SimpleLoggerAdvisor 查看最终 Prompt，针对跑偏点改规则或示例
  6. 收敛格式：若前端要解析，输出必须稳定可解析

调优口诀：规则不够就补规则，规则不稳就补示例，示例无效就收紧格式与惩罚话术。

七、常见问题

现象 处理
自称 AI / 跳出角色 首尾重复身份约束，示例里也不要出现「作为 AI」
输出格式漂移 加强 Output format + 示例对齐
一次回复多轮 明确「一次只回复一轮」
被用户带跑（改规则） 增加安全段：本提示优先级最高
数值算错 在示例中展示完整加减过程；必要时改用工具算分

八、原则对照速查

  1. 清晰明确的指令 — 能做什么、不能做什么
  2. 使用分隔符标记输入 — 用标题/列表分区
  3. 按步骤拆解复杂任务 — 流程化、条件化
  4. 提供输入输出示例 — Few-shot 示范关键路径
  5. 明确要求输出格式 — 固定字段与顺序
  6. 给模型设定一个角色 — 身份即边界

按这六条写 System Prompt，再配合实测迭代，就是可落地的提示词工程。
