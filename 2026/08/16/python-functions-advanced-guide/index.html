1.3 递归问题的特征

适合递归的问题通常具备：

特征 含义
可分解 大问题能拆成若干更简单的同构子问题
方案一致 子问题与原问题用同一套解法
依赖子问题 外层结果依赖内层结果

结构上必须同时有：

  • 结束条件：否则会无限递归
  • 递归体：负责缩小问题规模并调用自身

1.4 优缺点与使用场合

维度 说明
优点 代码往往更短，更贴近问题本身
缺点 调用层次深时栈开销大，通常比等价循环更慢、更耗内存
适用 问题天然递归、可读性优先、规模可控
慎用 高性能、深度很大、可用简单迭代清晰表达时

经验原则：能递归解决的问题通常也能用迭代解决。当递归更自然、更容易调试，且不强调极致性能时，可以优先递归；否则优先循环或显式栈。

4. 什么是高阶函数

把函数作为参数传入，或返回另一个函数，这样的函数称为高阶函数。它是函数式编程思想的重要体现：把“做什么操作”抽成可组合的小函数，减少重复循环骨架。

Python 同时支持：

  • 面向对象：类、对象、继承、封装
  • 函数式风格：高阶函数、lambda、递归等

二者并不互斥。数据处理、转换流水线等场景，函数式写法往往更紧凑。

7. 内置高阶函数 filter

filter 用布尔函数筛选序列元素，返回迭代器。函数返回 True 则保留，返回 False 则丢弃。

语法：filter(操作函数, 序列)

注意：filter / map 返回的是惰性迭代器，需要 list(...) 才能立刻看到全部结果；同一迭代器只能完整消费一次。

8. 内置高阶函数 sorted

sorted 返回排序后的新序列，不修改原序列。

语法：sorted(序列[, key=..., reverse=...])

  • reverse=False：升序（默认）
  • reverse=True：降序
  • key：传入“如何从元素提取排序依据”的函数

与列表原地排序 list.sort(...) 的区别：

方法 是否改原列表 返回值
sorted(seq, ...) 否 新列表
seq.sort(...) 是 None

key 只需要函数对象本身（如 len、str.lower），不需要写成 len(x) 这种“已经调用”的形式。

9. 学习小结与实践建议

主题 关键点
递归 必须有结束条件；适合同构子问题；注意栈深度
函数对象 可赋值、可传参、可返回、可挂属性
lambda 适合短回调；复杂逻辑改用 def
map 一一变换，返回迭代器
reduce 折叠合并，需从 functools 导入
filter 按布尔条件筛选
sorted 生成新序列；用 key 指定排序依据

实践建议：

  1. 先写清楚普通 def，再考虑是否值得抽成 lambda / 高阶函数。
  2. 递归写完后，优先检查结束条件与问题规模是否在缩小。
  3. map / filter 记得消费迭代器；需要多次遍历时先转成 list。
  4. 排序优先考虑 key=，少写复杂的比较函数。

把“函数当作值来传递”，是从基础语法走向函数式数据处理的关键一步。
