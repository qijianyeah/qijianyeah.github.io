Python 内存分析完全指南：不可变对象、可变对象与自定义实例

理解 Python 的内存模型，比死记“传值还是传引用”更有用。变量名保存在栈侧，真正的对象在堆上；赋值改的是“指向谁”，就地修改改的是“对象内部”。

1. 先建立心智模型

Python 中几乎一切都是对象。观察一个对象，通常看三件事：

维度 含义 常用查看方式
身份 identity 对象在一次运行中的唯一标识 id(obj)
类型 type 对象支持哪些操作 type(obj)
值 value 对象表达的数据内容 直接打印或访问属性

教学图里常把内存画成：

  • 栈：保存变量名，以及它当前指向的对象标识
  • 堆：保存真正的对象（类型、值、内部引用）

变量更像标签，不是“装满数据的盒子”。a = b 的含义是：让 a 与 b 指向同一个对象，而不是复制一份新的内容。

注意：id() 的具体数值只在当前进程、当前时刻有意义，不同运行会变化；下文配图中的地址是示意编号，不要当成固定常量。

2. 不可变对象的内存行为

2.1 哪些对象是不可变的

不可变对象不能在原地改内容；“修改”通常意味着创建新对象，再让变量指向新对象。

常见不可变类型：

  • int
  • float
  • bool
  • str
  • tuple

2.2 赋值：变量绑定到对象

执行后，栈上的 name 保存一个引用，堆上存在一个字符串对象，包含 id、type=str、value='lili'。

2.3 重新赋值：旧对象不再被当前变量引用

第二次赋值不会改写 'lili' 本身，而是：

  1. 在堆上创建新的字符串对象 'feifei'
  2. 让 name 指向新对象
  3. 原来的 'lili' 若没有其他引用，后续可由垃圾回收回收

2.4 别名：多个变量指向同一不可变对象

name2 = name 不会复制字符串，只是再贴一张标签。两个变量指向同一个堆对象。

因为对象不可变，通过任一别名都无法改坏另一个变量“眼里的内容”；真正危险的是可变对象的别名共享。

3. 可变对象的内存行为

3.1 哪些对象是可变的

可变对象允许在保持对象身份不变的前提下，改写内部数据。

常见可变类型：

  1. list
  2. dict
  3. set

3.2 创建列表

栈上的 lst 指向堆上的列表对象。列表内部再保存对各个元素对象的引用。

3.3 就地修改：地址通常不变

lst[1] = 66 改的是列表内部第 1 个位置指向谁，列表对象本身的身份不变。因此：

  • id(lst) 通常保持不变
  • 所有指向该列表的别名，都会立刻看到新内容

前者是原地改；后者是让变量指向另一个列表。

操作 是否新建容器 常见效果
lst[i] = x / append / update 否 身份不变，别名共享变化
lst = [...] / lst = lst + [...] 是 身份变化，原对象是否存活取决于还有没有引用

4. 经典易错题：函数参数里的赋值与原地修改

先看题目：

4.1 调用时发生了什么

调用 fun(n1, n2) 时：

  • arg1 与 n1 一开始指向同一个整数对象 11
  • arg2 与 n2 一开始指向同一个列表对象 [22, 33, 44]

4.2 为什么 n1 不变，n2 会变

  1. arg1 = 100
    这是重新绑定局部变量。arg1 改指向新的整数 100，与外面的 n1 脱钩。整数又是不可变对象，所以外面的 n1 仍是 11。

  2. arg2.append(10)
    这是就地修改共享列表。arg2 没有换对象，只是改了列表内容。外面的 n2 指向同一列表，因此也会变成 [22, 33, 44, 10]。

一个实例创建后，常见布局可以这样理解：

  1. 变量 stu 指向堆上的 Student 实例
  2. 实例通过 __dict__（或等价属性存储）保存属性名到对象的映射
  3. name、age 各自指向独立的字符串对象和整数对象
  4. 类本身的定义、方法代码位于类对象 / 代码区，实例通过类型信息找到方法

6. 学习小结与实践建议

场景 关键判断
不可变对象“修改” 几乎总是新建对象 + 变量重新绑定
可变对象修改 可能原地改，身份不变，别名会受影响
a = b 共享引用，不是深拷贝
函数参数 看你是“换标签”还是“改对象内部”
自定义实例 实例保存属性引用，类保存行为模板

实践建议：

  1. 遇到意外共享时，先打印 id()，分清“同一个对象”还是“值碰巧相同”。
  2. 需要隔离可变数据时，明确使用 copy()、deepcopy() 或新建容器。
  3. 写函数时，把“是否允许修改入参”写进命名或文档；默认不要偷偷 append / pop。
  4. 画一张“变量 → 对象 → 内部引用”草图，往往比背术语更快定位问题。

把“赋值”和“就地修改”分开看，Python 里绝大多数内存相关的坑都会清晰很多。
