Claude Code 安装与接入 DeepSeek 完全指南

Claude Code 是 Anthropic 的终端 / VS Code AI 编程助手。DeepSeek 提供 Anthropic 兼容接口后，只需改 Base URL、Token 和模型映射，就能继续用 Claude Code 的交互方式，把推理后端切到 DeepSeek。本文先把 Git、Node、npm、网络与 API Key 等环境装齐，再讲 Claude Code 安装与 DeepSeek 接入。

1. Claude Code 是什么

Claude Code 是面向编程场景的 Agent 工具，常见形态有两种：

形态 说明
CLI 终端里运行 claude，在项目目录内读代码、改文件、执行命令
VS Code Extension 在编辑器侧边栏开会话，读写当前工作区

它默认走 Anthropic API。把 ANTHROPIC_BASE_URL 指到兼容网关后，请求格式不变，后端可以换成 DeepSeek。

2. 为什么接入 DeepSeek

常见动机：

  1. 继续使用 Claude Code 的交互与工具链
  2. 按 DeepSeek 计费与额度使用模型
  3. 不改业务代码，只改环境配置即可切换后端

注意边界：

  • 这是 API 兼容接入，不是把 Claude 官方模型换成 DeepSeek 同名模型
  • Claude Desktop 的 OAuth 登录路径通常读不到这套 ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN，本文以 CLI / VS Code 扩展 为准
  • 远端控制（Remote Control）等依赖 api.anthropic.com 的能力，在自定义 Base URL 下一般不可用

3. 环境安装（必做）

把 Claude Code 跑起来并接到 DeepSeek，本地至少要准备齐下面几项。缺一项后面就会卡在「装不上 / 找不到命令 / 鉴权失败」。

下文以本机已跑通的环境为基准：你可以对照表格复现同一套组合；其他系统见各小节的通用安装步骤。

8. 模型选择与映射

DeepSeek 当前常用模型 ID（以官方文档为准，会随版本更新）：

模型 ID 典型用途
deepseek-v4-pro / deepseek-v4-pro[1m] 复杂编码、深度推理
deepseek-v4-flash / deepseek-v4-flash[1m] 更快、更轻量的日常任务

在 Anthropic 兼容接口上，若传入不受支持的 Claude 模型名，服务端可能自动映射到 deepseek-v4-flash。官方也说明过大致映射关系：

Claude 名称前缀 常见映射
claude-opus* deepseek-v4-pro
claude-sonnet* / claude-haiku* deepseek-v4-flash

更稳妥的做法仍是：在 settings.json 里显式写 DeepSeek 模型 ID，避免依赖隐式映射。

旧别名如 deepseek-chat、deepseek-reasoner 可能逐步退役，新配置优先用 deepseek-v4-*。

11. VS Code 扩展方式

  1. 安装 Claude Code VS Code Extension
  2. 使用与 CLI 相同的 ~/.claude/settings.json
  3. 搜索并勾选 claudeCode.disableLoginPrompt（避免一直卡在官方登录页）
  4. 打开项目 → 侧边栏 Claude Code → New session

扩展读的是用户级配置文件，因此优先把 DeepSeek 配进 settings.json，不要只 export 在某个终端会话里。

12. 常见问题

12.1 EBADENGINE / 安装警告

Node 版本低于 Claude Code 声明的下限。按第 3.3 节升到 Node 22+ 后重新全局安装。

12.2 command not found: claude

  • 确认已执行 npm install -g @anthropic-ai/claude-code
  • 确认 $(npm prefix -g)/bin 已在 PATH（见第 3.4、4.1 节）
  • 改完 ~/.zshrc 后必须 source 或新开终端

12.3 command not found: git（尤其 Windows）

按第 3.2 节安装 Git，并重新打开终端。Claude Code 在 Windows 上依赖 Git 环境。

12.4 401 / 鉴权失败

核对：

  • Key 是否完整、无多余空格或引号
  • 使用的是 ANTHROPIC_AUTH_TOKEN（不是只写了 OpenAI 风格的别处变量）
  • Base URL 是否精确为 https://api.deepseek.com/anthropic
  • 本机能否访问 https://api.deepseek.com（第 3.5 节）

12.5 仍在走 Anthropic 或要求登录

  • VS Code：确认 disableLoginPrompt 已开，且 settings 已被扩展读到（重启编辑器）
  • CLI：确认当前 shell 没有覆盖错误的环境变量
  • Desktop 客户端：本文方案不适用

12.6 模型名无效

改用官方当前 ID：deepseek-v4-pro / deepseek-v4-flash（含或不含 [1m] 以平台文档为准）。不要继续依赖已退役别名。

12.7 claude doctor 提示 Remote Control 不可用

自定义 Base URL 时的预期现象，不代表安装失败。

12.8 npm 全局路径与 nvm 冲突

若 ~/.npmrc 固定了 prefix，nvm 可能提示不兼容。可继续用固定前缀安装 Claude Code，只要 which claude 能找到即可；或按 nvm 提示清理冲突配置后再装（见第 3.4 节）。

12.9 curl / npm 超时

多为代理或防火墙问题。检查 http_proxy / https_proxy，或换网络后重试第 3.5、3.8 节探测。

13. 小结

步骤 要点（对照本机）
环境 macOS 15.7.7 arm64 + zsh；Git 2.39.5；nvm → Node v22.23.2 / npm 10.9.8；~/.npm-global；DEEP_SEEK_KEY
安装 npm i -g @anthropic-ai/claude-code → 本机 2.1.233 @ ~/.npm-global/bin/claude
接入 Base URL = https://api.deepseek.com/anthropic
鉴权 ANTHROPIC_AUTH_TOKEN ← 由 DEEP_SEEK_KEY 写入
模型 deepseek-v4-pro[1m] / deepseek-v4-flash[1m]
推荐落点 ~/.claude/settings.json（权限 600）
验证 第 3.1 / 3.9 节检查 → claude doctor → 进项目跑 claude

顺序固定为：先对齐第 3.1 节本机环境 → 再装 Claude Code → 再写 DeepSeek 路由配置。环境没齐时不要急着改 settings.json，否则问题会叠在一起难排查。
