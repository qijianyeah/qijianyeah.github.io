Python 模块与包完全指南：自定义模块、包结构、pip 与虚拟环境

项目稍大一点，就不能把所有代码塞进一个文件。Python 用模块组织代码，用包管理模块，再用 pip 安装第三方库，用虚拟环境隔离依赖。本文按这条主线把概念一次讲清。

1. 什么是模块

在 Python 中，一个 .py 文件通常就是一个模块（Module）。可以把模块理解成工具箱：把相关代码集中放在一起，需要时再导入使用。

一个模块里可以放：

内容 例子
变量 num = 100
函数 def test(a, b): ...
类 class User: ...
常量 MAX_RETRY = 3
可执行语句 导入时会执行的初始化代码

目的只有一个：按功能拆分代码，统一管理。

2. 为什么要使用模块

如果所有逻辑都写在一个文件里，文件会越来越难读、难改、难协作。使用模块通常能带来：

  1. 结构更清晰
  2. 复用更容易（一次编写，多处导入）
  3. 团队可并行开发不同模块
  4. 维护成本更低
  5. 降低不同功能区的命名冲突风险

自定义模块 自己编写的 .py 文件 my_module1.py
第三方模块 他人发布，需额外安装 requests、numpy

4. 自定义模块

每个 Python 文件都可作为模块，模块名通常就是去掉 .py 后的文件名。

4.1 命名规则

  • 符合标识符规则：字母、数字、下划线；不能以数字开头；不能是关键字；不能含空格
  • 见名知意，大小写敏感
  • 推荐小写加下划线，如 add_num.py、login.py
  • 不要与标准库同名，否则可能导入到错误模块

6. 模块搜索顺序

执行 import my_module1 时，解释器会按顺序查找，找到即停止；找不到则抛出 ModuleNotFoundError。

大致顺序：

  1. 当前工作目录 / 脚本所在项目目录
  2. sys.path 中的其余目录（标准库、site-packages、虚拟环境等）

7. __all__ 控制星号导入

在模块顶层定义 __all__（列表或元组，元素为字符串），可限制 from module import * 能导入哪些公共名称。

注意：__all__ 只影响 from module import *；import module 或 from module import testB 仍然可以显式导入。

8. 包：用目录组织模块

8.1 什么是包

当模块越来越多时，用文件夹把它们组织起来。传统上，一个包含 __init__.py 的目录就是一个包（Package）。包里可以有多个模块，也可以有子包。

说明：Python 3.3 起也支持无 __init__.py 的命名空间包；入门阶段仍建议显式放置 __init__.py，语义更直观。

10. 全局环境与虚拟环境

10.1 全局环境

安装 Python 时创建的默认运行环境。所有项目默认共用，刚学时 pip install 的包通常都装在这里。

问题是：项目 A 需要 Django 2，项目 B 需要 Django 4，装在同一全局环境里很容易互相冲突。

10.2 虚拟环境

虚拟环境是相对独立的 Python 运行环境，通常建在项目目录内，每个项目可拥有自己的一套依赖。

11. 学习小结与实践建议

主题 关键点
模块 .py 文件；可放变量、函数、类
__name__ 区分“直接运行”与“被导入”
导入 优先 import module，慎用 import *
搜索路径 当前目录 → sys.path
__all__ 只约束星号导入
包 目录 + __init__.py（经典模型）
pip / PyPI 安装与管理第三方库
虚拟环境 按项目隔离依赖

建议练习：

  1. 写一个自定义模块，并用五种导入方式分别调用。
  2. 建一个包含两个子模块的包，配置 __init__.py 与 __all__。
  3. 新建虚拟环境，安装 requests，写一个最小请求脚本。

把“模块—包—第三方库—虚拟环境”这条链走通后，Python 项目结构就会清晰很多。
