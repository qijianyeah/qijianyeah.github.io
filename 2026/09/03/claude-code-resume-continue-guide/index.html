Claude Code 会话恢复：claude --continue 与 --resume 用法详解

发表于2026-09-03|更新于2026-09-03|AI 工具实践
|浏览量:

Claude Code 会把每一次对话持续写到本机，任务跨午休、跨过夜、甚至跨目录，都可以原样接上，不必重新交代上下文。日常最常用的两个入口是 claude --continue 和 claude --resume：前者直接打开「当前目录最近一次交互会话」，后者按名称、ID 或选择器精确挑一次会话。

桌面应用、网页版 Claude Code、VS Code 扩展各自维护独立的会话历史。本文只讲 CLI。

1. 会话是什么

会话（session）是绑定到项目目录的一份已保存对话。你一边工作，Claude Code 一边把它写成本地 transcript，退出、跑 /clear，甚至机器重启，都可以再打开同一份记录。

一次会话不只是聊天记录，还带上当时用的模型、agent、权限模式、尚未过期的定时任务等状态。因此「恢复会话」的正确理解是：把对话和当时保存下来的运行状态一起接回来，而不是只把文字贴回上下文。

恢复入口有五条，按使用频率排：

命令 作用
claude --continue 恢复当前目录最近一次交互会话
claude --resume 打开会话选择器
claude --resume <名称或 ID> 按名称或会话 ID 直接恢复
claude --from-pr <编号或 URL> 打开选择器，只列出与该 PR / MR 关联的会话
/resume 已在会话内时，切换到另一段对话

claude -p（非交互 / SDK）和 Agent SDK 创建的会话，默认不出现在选择器和 claude --continue 里。仍然可以用会话 ID 精确恢复：

2. continue 与 resume 怎么选

两条命令都是「接着上次聊」，差别在找谁、找多广、要不要你动手选。

维度 claude --continue（-c） claude --resume（-r）
目标 当前目录最近一次交互会话 指定会话，或打开选择器让你挑
要不要参数 不需要 可空、可名称、可 ID
跳过哪些会话 后台会话、claude -p / SDK 会话、首条提示是 /loop 的会话 选择器同样隐藏 -p / SDK 会话，以及首条是 /loop 的会话；后台会话会显示并标 bg
/add-dir 把当前目录加进来的会话也算「本目录会话」 选择器和按名称搜索同样包含这类会话
跨项目 只看当前目录（含 /add-dir） 传 ID 时：先搜当前项目及其 git worktree，再搜本机其他项目（v2.1.223 起）
典型场景 午休回来、终端关了、SSH 断了，立刻接着干 并行多任务、跨目录、按名字或 ID 接回某一次

选型可以记成一句话：

  • 刚才那次 → --continue
  • 某一次、某一个名字、某一个 ID → --resume
  • 已经在会话里，只是想换一段对话 → /resume

这会加载当前目录最近一次交互会话。没有可继续的会话时，打印 No conversation found to continue 并退出。

适合「终端关了、电脑休眠了、SSH 掉了」这种场景。任务还在这个仓库里，上下文不用重讲。

3.2 它会跳过什么

交互模式下的 --continue 不会接上：

  • 后台会话（--bg / background agent）
  • claude -p 或 Agent SDK 创建的会话
  • 第一条提示就是 /loop 的会话

中途才跑 /loop 的会话不受影响，仍然可以被 --continue 找到。v2.1.211 之前，对话早期执行 /loop 会让该会话从选择器里永久消失；之后的版本只看「是不是首条提示」。

/add-dir 把当前目录加进去的会话，算作本目录会话，--continue 会纳入。

5. 会话选择器

claude --resume 不带参数，或会话内执行 /resume，都会打开交互式选择器。

5.1 默认列出什么

会话按项目目录存放。默认列表包括：

  • 当前 worktree 的会话，后台会话带 bg 标记
  • 在别处启动、但用 /add-dir 加入了当前目录的会话

首条提示是 /loop 的会话不出现。claude -p / SDK 会话也不出现。

v2.1.169 起，/cd 会把会话搬到新目录的项目存储里，之后只出现在新目录的选择器中。v2.1.196 起，即便崩溃或强制退出，也不会再回到旧目录列表。

从同一仓库的另一个 worktree挑一条会话，会在原 worktree 里恢复；那个 worktree 已经不存在时，则在当前目录恢复。从无关项目挑一条，Claude Code 不会直接切过去，而是把 cd + 恢复命令复制到剪贴板。那个项目目录已经不存在时，改为在当前目录恢复，避免复制一条注定失败的 cd。

5.2 快捷键

快捷键 作用
↑ / ↓ 在会话之间移动
→ / ← 展开或折叠分组会话
Enter 恢复高亮会话
Space 预览会话内容；部分终端也可用 Ctrl+V
Ctrl+R 重命名高亮会话
/ 或除空格外的可打印字符 进入搜索；可粘贴 PR / MR URL
Ctrl+A 列出本机全部项目的会话；再按一次回到当前仓库
Ctrl+W 列出当前仓库全部 worktree 的会话；仅多 worktree 仓库显示
Ctrl+B 只看当前 git 分支的会话；再按一次看全部分支
Esc 退出选择器或退出搜索

每一行展示：你起的名字（没有则用 AI 生成的标题 / 摘要 / 第一条提示）、距上次活动的时间、git 分支、文件大小。Ctrl+A 展开到全机后，还会显示项目路径。

/branch 或 --fork-session 产生的会话有独立 ID，单独占一行。同一会话出现多条记录时会收成一组，按 → 展开。

从 claude --resume 选择器进入失败时，打印 Failed to resume the conversation 和一条可重试命令，然后以退出码 1 退出。从会话内 /resume 失败时，只报告失败，当前对话继续跑。

6.2 没起名时的两种标签

未命名会话仍有两个系统标签，只有生成标题能当恢复句柄：

标签 长什么样 能否 claude --resume <它>
默认显示名 工作目录名 + 两字符后缀，如 my-app-3f（v2.1.196+） 不能。传给 --resume / /resume 找不到
生成标题 用小模型（通常 Haiku 级）根据第一条提示写的短摘要 能，解析规则和你手起的名字相同

接受计划后，生成标题会换成基于计划的标题，同时替换运行中会话列表里的默认显示名。你自己 /rename 之后，这两种系统标签都会被替换。

7. 恢复时带回什么

7.1 会恢复的

  • 对话历史：完整记录，含工具调用和结果
  • 模型：继续用会话当时的模型。模型已下线、不在 availableModels 里、启动时用了 --model 或 ANTHROPIC_MODEL 一类环境变量、或走 Bedrock / Google Cloud Agent Platform / Microsoft Foundry 这类带部署 ID 的供应商时，模型不会按会话里的值恢复
  • Agent：用 --agent 或 agent 配置启动的会话，会带着它的系统提示、工具限制和模型继续。恢复时再传 --agent 可换成另一个。查找顺序：会话原来的目录（需已信任该工作区）→ 你当前恢复时所在的目录。两处都找不到时，退回默认工具和系统提示，并警告缺少哪个 agent
  • 权限模式：仅部分路径会恢复，见下一章
  • 仍在进行的 goal：会带过来；回合计数、计时器和 token 花费基线会重置
  • 未过期的定时任务：会恢复。后台 Bash 和 monitor 任务不会。/loop 任务在未过期时，--resume / --continue 也会接回来

7.2 不会自动恢复、需要你再传一遍的

原启动依赖过这些标志，恢复时要自己再带上：

  • --mcp-config
  • --settings
  • --plugin-dir
  • --fallback-model
  • --add-dir 加进来的目录

会话中途用 /add-dir 加的目录也不会恢复，但选择器仍会用它们来定位会话。

settings.json、settings.local.json 这类标准配置文件会在启动时重新读取，写在文件里的配置不必再传。

8. 权限模式怎么变

「恢复」不等于「权限模式原样回来」。走哪条入口，结果不一样。

恢复方式 权限模式
终端：claude --continue、claude --resume <ID>、名称唯一时的 claude --resume <名称>（均无 -p） 尽量恢复会话结束时的模式，但有例外，见下表
非交互：claude -p --resume / claude -p --continue 按一次新的 claude -p 会采用的模式启动；结束于 plan 且满足四个条件时除外
启动时的选择器：claude --resume、claude --from-pr、名称命中多条 不恢复存储的模式，按「现在这条命令行会开新会话」的模式启动
会话内 /resume 不恢复存储的模式，沿用你当前会话的权限模式

终端路径上，结束时的模式 vs 恢复后的模式：

会话结束于 终端恢复后
bypassPermissions 变成「新会话会采用的模式」。要再次绕过权限，启动时显式开，或在 user / --settings / managed settings 里设 permissions.defaultMode: "bypassPermissions"
plan 变成「新会话会采用的模式」
auto 仅当账号仍满足 auto 模式条件时保持 auto
Manual 若新会话会因内置默认进入 auto，则恢复为 Manual；若 settings 里的 defaultMode 生效，则用那个模式

也就是说：plan 和 bypassPermissions 不会在终端 --continue / --resume 时被静默接回来。这是刻意的安全选择。要覆盖恢复结果，启动时传 --permission-mode 或 --dangerously-skip-permissions。

非交互路径要恢复成 plan 模式，四个条件必须同时成立（需 v2.1.246+）：

  1. 传了 --permission-prompt-tool（这样 Claude Code 才能把计划拿出来让你批）
  2. 没传 --permission-mode 或 --dangerously-skip-permissions
  3. 没传 --fork-session
  4. 不是通过 channels 启动的这次运行

9. 超长会话从摘要恢复

Pro / Max 计划上，满足下面两个条件时，恢复后、你发出第一条消息前会弹出对话框：

  • 会话已闲置大约超过 1 小时
  • 会话超过 100,000 tokens

此时 prompt cache 已经过期，无论选哪一项，下一次请求都会把完整历史再处理一遍。三个选项差在之后每次请求带多少历史：

选项 行为 代价
Resume from summary 立刻跑一次 /compact：对完整历史做摘要，然后用摘要 + 最近几轮对话 + 最多 5 个最近读过的文件替换历史 后续请求更便宜，但摘要丢掉的细节不在上下文里了
Resume full session as-is 原样加载。发出第一条消息后，完整历史重新处理并重新缓存 每个细节都还在，单次费用随对话变长而涨
Don’t ask me again 按完整会话恢复，并且以后不再弹出

长会话费用往上走，主要就来自「每次请求都要带着越来越长的历史」。摘要恢复是在保细节和控费用之间做取舍。

10. 分支与 fork-session

想在已有上下文上试另一条路、又不污染原来的 transcript，就分支。原会话原封不动留在磁盘和选择器里。

10.1 会话内：/branch

不写名字时，用对话第一条提示当分支名。v2.1.198 起，即使已经 compact 过，也会穿过摘要去看原来的第一条提示；更早版本会落到字面名字 Branched conversation。

确认时会打印两个会话 ID：你现在所在的新分支，以及未改动的原会话。回到原会话：

/branch 是同一进程内切到新 transcript：

状态 /branch 之后
对话历史 复制到分支，截止到你执行 /branch 的那一刻
「允许此会话」的权限批准 带过去（还是同一个进程）
进行中的后台 subagent / 后台 Bash 继续跑，输出出现在新分支，不出现在原会话
Remote Control 连接 保持连接，手机 / 浏览器跟着进新分支

和 --continue / --resume 组合，开一个新进程、新会话 ID：

11. 会话存在哪

11.1 默认路径

transcript 是 JSONL，默认：

<项目目录名> 由工作目录路径生成：非字母数字字符换成 -。转换后超过 200 字符时，截到 200 再拼上完整路径的哈希，避免撞文件系统限制。

每一行是一条消息、一次工具调用或一条元数据。这是 Claude Code 的内部格式，版本之间会变，不要自己解析这些文件做生产逻辑。给人看用 /export。

11.2 可调的存储行为

目的 设置 写在哪
把存储挪出 ~/.claude CLAUDE_CONFIG_DIR 环境变量
自己指定 <项目目录名> CLAUDE_CODE_PROJECT_DIR_NAME（必须同时设 CLAUDE_CONFIG_DIR） 环境变量，v2.1.234+
改 30 天保留期 cleanupPeriodDays settings.json
所有模式都不写 transcript CLAUDE_CODE_SKIP_PROMPT_HISTORY 环境变量
单次 -p 不落盘 --no-session-persistence CLI

claude rm <id> 只是把后台会话从列表里拿掉，本地 transcript 还在，仍可用 claude --resume 打开。真正清空某个项目的本地状态用 claude project purge。

11.3 和 Remote Control 的关系

用 claude --remote-control 或 /remote-control 开过远程控制的对话，之后 claude --continue / claude --resume 会尝试按会话里记录的 Remote Control 连接重连。重连失败时本地会话照常运行，只是暂时没有远程控制；可再跑 /remote-control 重试，或开一条新的 claude --remote-control。

12. 常见问题

Q：--continue 找不到刚才的对话？

先确认当前目录对不对。--continue 看的是「这个目录的最近一次交互会话」，在家目录或另一个仓库里跑会得到 No conversation found to continue。若刚才是 claude -p、后台 agent，或首条就是 /loop，交互模式下的 --continue 会故意跳过，改用 claude --resume <session-id>。

Q：记得大概叫什么，但 --resume 名字 进不去？

名称必须精确匹配。模糊名字时，claude --resume 关键词 会打开选择器并预填搜索；/resume 关键词 则直接报错。默认显示名（如 my-app-3f）不是恢复句柄，要用你起的名字或 AI 生成的标题。

Q：两个终端同时 --resume 同一条会话，记录乱了？

两边会写进同一份 transcript。要并行试两种方案，用 --fork-session 或 /branch。

Q：恢复后 MCP / 额外目录不见了？

--mcp-config、--add-dir、--plugin-dir、--settings、--fallback-model 都不会随会话自动回来，恢复时再传一遍。中途 /add-dir 加的目录同样不恢复。

Q：恢复后突然不在 plan / bypass 模式了？

终端路径不会把 plan 和 bypassPermissions 静默接回来。选择器和 /resume 更是完全不恢复存储的权限模式。需要哪种模式，启动时显式传 --permission-mode。

Q：选择器里没有另一个项目的会话？

默认只看当前 worktree。Ctrl+W 看本仓库全部 worktree，Ctrl+A 看本机全部项目。从不相关项目挑一条时，CLI 复制 cd 命令，而不是直接在当前目录打开。

Q：后台会话 claude rm 之后还能回来吗？

能。claude rm 只从后台列表移除，transcript 仍在本地，claude --resume 可以打开。

13. 小结

  • 刚才那次、还在这个目录：claude --continue / claude -c
  • 某一次、某一个名字、某一个 ID：claude --resume / claude -r
  • 已经在会话里要换一段：/resume
  • 和某个 PR 有关：claude --from-pr
  • 想试另一条路、留下原文：--fork-session 或 /resume 之前先 /branch
  • 并行任务：启动时 claude -n 有含义的名字，回来时 claude --resume 那个名字
  • plan / bypass 权限、MCP、额外目录：不要默认它们会跟着回来，需要就再传一遍
